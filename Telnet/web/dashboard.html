Local and remote log-in

slide: Local and remote log-in

Logged in locally, keystrokes go from the terminal driver straight to the operating system. Logged in remotely, the TELNET client takes them from the terminal driver and sends them through TCP/IP and the Internet. On the server they enter a pseudoterminal driver, so the programs there believe a real terminal is attached. Type in the terminal: every key travels this path and the echo comes back.

02

Network Virtual Terminal (NVT)

slide: Concept of NVT

Client and server may use different character sets, so both translate to one common NVT character set on the wire. A byte whose highest bit is 0 is a data character (7-bit ASCII). A byte whose highest bit is 1 is a control character, and it only counts as a command after IAC (255).

Live: the last bytes on the wire, bit by bit
MSB 0: data characterMSB 1: control characterclient → serverserver → client
Connect through the wire tap and type: each byte appears here as 8 bits.
Line endings in the NVT: CR LF = newline, CR NUL = carriage return only. A data byte 255 is sent twice (FF FF) so it is not mistaken for IAC.
03

Control characters & embedding

slides: NVT control characters, An example of embedding

Every control character starts with the high bit set. Rows light up when that byte crosses the wire, and the count is live. Use send to push a command into your session.

An example of embedding

The user types cat filea, notices the mistake, and presses erase character. The client embeds IAC EC in the data stream, then types 1, all in one TCP segment. The server applies the erase before running the command.

63 61 74 20 66 69 6C 65 61 FF F7 31 0D 0A
The server echoes a, then on IAC EC erases it on screen (\b \b) and in its line buffer, then echoes 1. It executes cat file1.
04

Options

slide: Options

Options change how the NVT behaves. Each has a code, and each side of the connection turns it on or off separately. The columns show the live state negotiated by your session (RFC 1143 states).

05

Option negotiation

slides: character set for negotiation, Echo option, Suboption negotiation

The same byte means different things depending on the state of the conversation: WILL may be an offer or an acceptance. The server tracks each option with the RFC 1143 states and labels every message it sends or receives. Counts below are from your session.

Why RFC 1143 matters: the negotiation loop

Both ends turn ECHO on at the same moment, then the server changes its mind. Naive endpoints acknowledge everything and bounce messages forever. Q-method endpoints finish in 4 messages and agree.
