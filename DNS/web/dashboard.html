Nobody knows every name.
Everybody knows who to ask.

The naming tree is cut into zones. Each zone's server knows only its own names and who is in charge of each child. Ask the root about www.cse.myuniv.edu and it replies "ask .edu", together with that server's address (the glue). Every box below is a real DNS server on its own address.

02

Two ways to find a name:
recursive and iterative.

RD = recursion desired
RA = recursion available

Recursive resolution: every server that does not know the answer asks the next one for you and waits, so the question goes down the chain and the answer comes back up it. Iterative resolution: every server that does not know replies with a referral ("ask them"), and the resolver itself asks the next one. Both figures below come from real lookups on our servers. 03

One packet,
every byte explained.

RFC 1035 §4.1
header · question · answer · authority · additional

Our dig client sends one query to any server: ours, Google's 8.8.8.8, or a root server. It prints the reply byte by byte. Point at a byte to see what it means. Red-outlined bytes are compression pointers: a repeated name is replaced by two bytes pointing back to its first appearance.

04

The resolver's memory.

TTL · negative caching (RFC 2308)

Every record has a TTL set by its zone's owner: how many seconds others may remember it. The bars count down live. Negative answers (no such name) are remembered too, for the SOA's minimum. Without the cache, every lookup would start at the root.

05

The listings: zone files.

SOA · NS · A · CNAME · MX · TXT · PTR

These are what the authoritative servers serve, in BIND zone-file syntax. cse.myuniv.edu holds your Assignment 6 records. Add a record and it is live straight away; the resolver's cached copy of that name is dropped.

06

Forgery: poisoning the cache.

Kaminsky 2008 · RFC 5452 · draft 0x20

The resolver asks dns.cse.myuniv.edu for bank.cse.myuniv.edu, and that server takes 1.5 s to reply. During that window an attacker floods the resolver with forged replies saying bank = 6.6.6.6, one for each of the 65,536 possible query IDs. Whichever reply matches first is believed and cached for everyone.

POISONED The 2008 resolver

Fixed port, trusting

  • source port always 5399
  • 16-bit query ID is the only secret
  • no check of who answered
  • question matched without case
01.5 s
DEFENDED A modern resolver

Random everything

  • a new random source port for every query
  • random 16-bit ID
  • reply must come from the server asked
  • 0x20: random letter case, echoed exactly
01.5 s

On loopback, packets cannot be given a fake source address. So the "2008" resolver skips the source check, which is what IP spoofing achieves on a real network. The lasting fix is DNSSEC: answers are signed, so a forgery cannot be verified.
