Dijkstra: settle the nearest router, one at a time

link state · OSPF's SPF calculation

A link-state router has the full map (its LSDB). It starts with N' = {itself} and repeats: pick the not-yet-settled router with the smallest D, settle it, then check whether going through it gives any neighbour a cheaper path. Each Forward adds one row to the textbook table.

Bellman-Ford: neighbours swap vectors

distance vector · RIPv2 responses on UDP 520

A distance-vector router knows nothing about the map, only its links. Each round, every router sends its distance vector (one number per destination) to each neighbour as a real RIPv2 packet, then recomputes Dx(y) = min over neighbours v of c(x,v) + Dv(y). 4

Good news travels fast, bad news travels slowly

Kurose & Ross Fig. 5.7 · the routing loop

Three routers, settled. Then the x–y link changes cost. When it gets cheaper (4 → 1), the news spreads in a couple of rounds. When it gets dearer (4 → 60), y thinks "z can reach x for 5, so I'll go via z for 6". But z's 5 went through y. y and z now point at each other, a routing loop, and raise their prices by one each round until z's direct link (50) is finally cheaper.

5

Count to infinity: two routers

RIP · infinity = 16 · split horizon

A – B – C in a line, every link cost 1. The link B–C fails. B has no direct route to C any more, but A just said "C: 2". B believes it and picks "via A, 3". A hears B's 3, so A says 4, then B says 5… Each router is the other's next hop. RIP caps infinity at 16 precisely so this ends. Split horizon ("never tell a neighbour about a route you learned from it") stops it outright.

6

Three routers beat split horizon

RIP with split horizon + poison reverse

A, B and C form a triangle; D hangs off C. The link C–D fails. Split horizon and poison reverse are both on, and the network still counts to 16. A learned D from C, so it never tells C, but it does tell B. B tells C, and C tells A. The bad route travels round the triangle, A → B → C → A, and no rule about a single neighbour can see a loop of three. That is the case distance vector cannot fix.

7

The same failure with link state (OSPF)

LS Update · Router-LSA · sequence numbers

With link state, C and D each send a new Router-LSA (sequence number + 1) that simply omits the dead link. Flooding carries the fact itself ("the C–D link is gone"), not anyone's opinion of a distance. A copy with a sequence number a router already has is dropped. A link counts only if both ends list it. Everyone re-runs Dijkstra on the same map: no loop, no counting.

The same failure with path vector (BGP)

UPDATE · AS_PATH · loop detection · TCP 179

Now every router is an autonomous system (A = AS 100 … D = AS 400, which owns 10.4.0.0/16). An announcement carries the whole AS_PATH. A router that finds its own AS number in a received path rejects it. When C–D fails, A and B briefly fall back on each other's old paths (path exploration), but the next UPDATE they send says [100 200 300 400], and B sees AS 200 in it. The loop is caught after one round instead of counting to 16.
