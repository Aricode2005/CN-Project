01The route

Mail is pushed to the post office, then pulled home.

The sender's user agent hands the letter to an MTA over SMTP. It waits in the recipient's mailbox until the recipient's agent fetches it through an MAA, using POP3 or IMAP. The letters moving on this map are real lines exchanged by our servers.

02Posting

Write a letter. Our SMTP client posts it to our SMTP server.

Each reply in the ledger has a three-digit code and a plain-English meaning. After sending, the client files a copy in Sent with IMAP APPEND, just like Thunderbird. An outside address is relayed only after AUTH; with no smart host, the server writes back a bounce.

03The difference

Two devices, one mailbox. See what each protocol does to the post office.

Bob reads mail on a phone and a laptop. Give each device a protocol and press Check mail; every button runs our real client against our server. POP3 takes letters home, and in delete mode it empties the counter. IMAP leaves them at the counter, so every device sees the same state.

04Sorting

Inside the mailbox: pigeon-holes, UIDs, flags, and the letter taken apart.

Each folder is a pigeon-hole on the server, and each message is one .eml file with a permanent UID and its flags. POP3 can only reach INBOX; IMAP reaches every folder.

06Abroad

The same clients, sent abroad: Gmail, Outlook, any real server.

Implicit TLS on 993, 995 and 465; STARTTLS on 587. Gmail needs 2-step verification and an app password, not your normal password. Credentials go only to the server on this PC, are masked in the ledger, and are never stored.
